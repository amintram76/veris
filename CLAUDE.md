## Tools on the Site

### 1 — GP Practice List Size Comparison (`/tools/gp-list-sizes`)
Compare registered patient list sizes across practices, April 2019–present.
- Merger/anomaly detection flags months with >3× average monthly change (floor 500 patients)
- Organic growth compounding excludes merger months
- England total registered population comparison
- CSV export and print/export dialog
- Cross-links to GP map via `?practices=CODE1,CODE2`

### 2 — GP Practice Boundary Map (`/tools/gp-map`)
Interactive map of GP catchment boundaries.
- Search by name/code/ICB to overlay up to 8 colour-coded boundaries
- Click anywhere on map: finds 50 nearest practices, checks all 50 for point-in-polygon containment, shows all surgery sites (main + branches) with straight-line distances
- Cross-links to list size tool
- Boundary data: SCW CSU GeoJSON, 6,205 files in `public/gp-boundaries/`
- Background tiles: CartoDB Positron (light, designed for data overlays)

## Maintenance Tasks

### 🗓 Monthly — Update NHS patient register data
NHS Digital publishes around the **10th of each month**; run this a few days later.

```
node scripts/fetch-nhs-data.mjs
git add src/data/nhsData.generated.json
git commit -m "Update NHS GP list size data — [Month] [Year]"
git push origin main
```

> If the script exits with 0 practices parsed, the NHS CDN column names have changed again.
> Check `scripts/fetch-nhs-data.mjs` → `col()` calls in `parseAllPatientsCSV()` and `parseMappingCSV()`.

---

### 🗓 Quarterly — Refresh branch surgery data
Picks up new branch openings and (eventually) closures from NHS ODS.

```
node scripts/fetch-branch-data.mjs
git add src/data/gpBranchLocations.json src/data/gpDataMeta.json
git commit -m "Refresh GP branch surgery data from NHS ODS — [Month] [Year]"
git push origin main
```

> ⚠ NHS ODS data quality caveat: practices must notify ODS of closures.
> Closed branches may still appear until ODS is updated.
> The UI shows the fetch date and links to find-a-gp.nhs.uk for verification.

---

### 🗓 After NHS data refresh (if new practices have opened) — Re-geocode practice addresses
Only necessary if the monthly data refresh adds practices with ODS codes not previously seen.

```
node scripts/geocode-practice-addresses.mjs
git add src/data/gpPracticeAddresses.json src/data/gpDataMeta.json
git commit -m "Update GP practice address geocodes — [Month] [Year]"
git push origin main
```

> Takes ~2 minutes (63 batches of 100 postcodes via postcodes.io — free, no key needed).

---

### 🗗 Rarely — Update GP boundary data
Only when SCW CSU publish new or revised boundary files.

1. Copy new `.geojson` files into `C:\Users\amint\Documents\NHMP\GP catchment data`
2. Run:
```
node scripts/process-boundaries.mjs
git add public/gp-boundaries/ src/data/gpBoundaryCentroids.json
git commit -m "Update GP practice boundary data from SCW CSU"
git push origin main
```

> Large commit (~8 MB). Takes 30–60 seconds to process.

## Known Limitations & Gotchas

- **Sep 2021 data is null** — NHS did not publish that month. Expected and handled.
- **NHS CDN blocks non-browser User-Agents** — `fetch-nhs-data.mjs` uses browser-like headers to work around this. If it breaks, check headers.
- **NHS ODS branch closures lag reality** — practices must actively update ODS. The UI shows the fetch date and a caveat.
- **`react-leaflet` must stay at v4** — v5 requires React 19; this project uses React 18.
- **Polygon centroids ≠ practice locations** — `gpBoundaryCentroids.json` contains vertex-average centroids of the boundary polygons, which can be far from the actual surgery. Always prefer `gpPracticeAddresses.json` for distance calculations and map pins.
- **PowerShell heredoc syntax** — use `@'...'@` (single-quoted) for multi-line git commit messages, not bash `$(cat <<'EOF'...)`.
